2026-10-19 기준. 현재 실행·구조·기능 제한은 [README](../README.md), 협업·역할·자원 사용권은 [OPERATING.md](OPERATING.md)를 따릅니다. 이 문서는 최신 상태와 다음 작업을 위한 공유 인수인계입니다. 세부 실행/실패 기록은 비공개 자료와 Git 이력에 보존합니다.

## 검증 기준과 구현 계약

- 기본 HTTPS 전환의 실행 근거: Node748/748, Python131 중130통과·1skip(Python3.9 없음), 전체 격리Chrome102조건, 별도 모의 launcher5조건. 후속 lifecycle8은102의 부분집합이며 합산하지 않습니다. 소스 지문이 같은 검사만 명시적으로 재사용합니다.
- 실제 계정 결과와 합성 결과는 구분합니다. ACK·HTTP202·NOTIREAD status0·업로드 수락만으로 수신이나 상대방1 해제를 판정하지 않습니다.
- 기본 HTTPS 전환에서는 로그인/텍스트/읽음 및 업로드 wire 계약을 바꾸지 않았습니다. legacy LOCO fixtures는 모드를 명시해 기존 SHIP/POST/COMPLETE 단언을 보존했습니다. CLI 공백/등호형·누락/잘못된 옵션과 별칭 호환을 검사했습니다.
- 브라우저는 JPEG/PNG/WebP 원본20MiB/40M픽셀 → 최대변4096 → JPEG품질0.9/0.8/0.7 최대3회 준비 → 결과10MiB를 적용합니다. 투명 부분은 흰색이며 미리보기와 제출 바이트는 같습니다. 이는 로컬 인코딩이며 업로드 재시도가 아닙니다.
- 결과 불명 자동 재전송/방식 fallback 없음, 방·계정·요청 세대 격리와64비트 ID 보존을 유지합니다. 오픈채팅 본인/링크/권한 검증 없이 기능을 열지 않습니다.
- 독립 검토는 기존 빌트인 역할을 재사용한 읽기 전용 검토였습니다. 새 custom role 발견/실행이나 자식의 독립 런타임 검사를 주장하지 않습니다. 두 CLI/artifact 집계 지적은 수정했고 최종 실제 근거 범위도 재검토했습니다.
- 초기 실패·RED는 비공개 원본을 보존했습니다. fixture의 인증 대기/이력 준비/재생성 시점과 수집기 완료 플래그 교정은 제품 결함과 구분합니다. 과거 vendor 하네스는 manifest 검증 자료로 보존합니다.

## 문제 재현 시 조사 순서

현재 성공 사례를 전체 미해결로 되돌리지 않습니다. 남은 실패가 재현됐을 때 다음 순서로 목표·입력·소유 파일·의존성·통과 기준·자원 lease를 확정합니다.

1. **상대방 읽음1**: 권한 있는 APK 확보·버전/SHA256 → REA/JADX 정적 경로 → 별도 승인된 공식 앱 동작 비교 → 상태/프로토콜 계약 → 최소 수정 → 합성/로컬 통합 → 승인된 상대방 동일 메시지1 확인.
2. **사진 발송**: 원본 준비·업로드·메시지 등록·수신 단계를 분리해 현 소스/고정 공개 소스/APK 근거를 비교합니다. LOCO의 ECONNRESET 주체·원인은 HTTPS 성공만으로 확정하지 않습니다. 임의 WRITE·프로필 위장·자동 재시도는 도입하지 않습니다.
3. **대화방 이름**: CHATINFO·메타·참가자·오픈링크와 로컬 별칭 우선순위를 대조하고 정확한 방/종류 매핑을 검사합니다.
4. **오픈채팅**: 종류·링크·본인 역할/mute/권한을 보수적으로 확인한 뒤 텍스트·사진·답장·읽음을 각각 설계/검증합니다.

APK/Android·REA 도구와 권한은 해당 PC에서 확인합니다. REA CLI·별도 MCP subprocess·현재 세션 직접 MCP 연결을 구분하고, 샘플 APK 성공을 카카오톡 분석 성공으로 바꾸지 않습니다. APK·원본을 외부 서비스에 업로드하지 않습니다.

## 재개와 저장소 관리

새 clone은 README의 런타임/고정 소스/패키지를 준비하고 운영 문서대로 새 작업을 시작합니다. 과거 agent ID·계정 승인·다른 PC의 절대 경로/장부를 재사용하지 않습니다. 서버 코드 적용에는 사용자 초안 보관·세션 정리 후 전체 stop/start/open/새QR이 필요합니다.

공유 파일은 제품/테스트/준비 도구·잠금 파일·라이선스·UI 시안·하네스 정의입니다. 로컬 원본·샘플·실행 근거는 기존 Git 제외를 유지합니다. 사용 종료가 입증된 합성 브라우저 프로필은 검증된 압축 보관 후 원본 폴더를 정리하고, 프로세스 상태가 불명확한 프로필은 보존합니다. 실제 사용자 Chrome·LOCALAPPDATA 인증/설정·사용 중인 런타임/의존성은 정리 대상으로 삼지 않습니다.

커밋 전에는 Git 후보와 미추적 신규 모듈을 함께 확인하고 민감정보·raw 응답·원본 포함 여부를 검사합니다. 커밋/push는 별도 사용자 요청 범위에서 수행하며 force push하지 않습니다.
