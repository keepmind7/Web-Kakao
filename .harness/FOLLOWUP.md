## 검증 기준과 구현 계약

- 기본 HTTPS 전환의 실행 근거: Node748/748, Python131 중130통과·1skip(Python3.9 없음), 전체 격리Chrome102조건, 별도 모의 launcher5조건. 후속 lifecycle8은102의 부분집합이며 합산하지 않습니다. 소스 지문이 같은 검사만 명시적으로 재사용합니다.
- 2026-10-20 진단 수정 후 최종 근거: Node829/829(신규81 포함, --test-concurrency=2), Python130통과·1skip, 격리Chrome106조건(기존102+신규4). 타이머 단언이 실패한 병렬 실행과 최초 RED/fixture·권한 오류는 비공개 수정 장부에 보존하며 기존 단언은 완화하지 않았습니다. 수정 후 실계정 회귀는 미실행입니다.
- 같은 날 D2 후속 보완 실행은 Node845/845(기존829+후속16, --test-concurrency=2), 격리Chrome114조건(기존106+후속8)입니다. 실제 두 합성 탭에서 B202→A409 후 자동 이력/문맥/읽음/선택 재발급0과 B유지, 보류 중 포커스 무효화, 재선택·수동이력·재접속 제어를 확인했습니다. Python은 위 독립 재검토 근거이며 이번 UI 전용 후속에서 재실행하지 않았습니다. 과거 보고서·manifest와 실패/중간 로그를 보존하고 후속 지문을 별도로 기록합니다.
- 수동 조회 P3까지 보완한 최신 실행은 Node853/853(위845+새8), 격리Chrome115조건(위114+상태 확인 중 실제 버튼 클릭·복구1)입니다. 독립 검토와 새12파일 manifest로 범위를 대조했습니다. 첫 Chrome은 조회1회 이후 시험에서 멈춘 poll을 재개하지 않아 완료 snapshot 확인이 timeout됐고, 시험의 정상 poll 재개를 보완한 최종 전체 실행이 통과했습니다. 제품·기존 assertion은 추가 변경하지 않았습니다. 실제 계정·Python 재실행은 미실행입니다.
- 실제 계정 결과와 합성 결과는 구분합니다. ACK·HTTP202·NOTIREAD status0·업로드 수락만으로 수신이나 상대방1 해제를 판정하지 않습니다.
- 기본 HTTPS 전환에서는 로그인/텍스트/읽음 및 업로드 wire 계약을 바꾸지 않았습니다. legacy LOCO fixtures는 모드를 명시해 기존 SHIP/POST/COMPLETE 단언을 보존했습니다. CLI 공백/등호형·누락/잘못된 옵션과 별칭 호환을 검사했습니다.
- 브라우저는 JPEG/PNG/WebP 원본20MiB/40M픽셀 → 최대변4096 → JPEG품질0.9/0.8/0.7 최대3회 준비 → 결과10MiB를 적용합니다. 투명 부분은 흰색이며 미리보기와 제출 바이트는 같습니다. 이는 로컬 인코딩이며 업로드 재시도가 아닙니다.
- 결과 불명 자동 재전송/방식 fallback 없음, 방·계정·요청 세대 격리와64비트 ID 보존을 유지합니다. 오픈채팅 본인/링크/권한 검증 없이 기능을 열지 않습니다.
- 사진 확정 결과 회수는 기존 clientId/방/종류를 대조하며 새 텍스트 요청과 별도로 정리합니다. 같은 방/log/본인/검증된 종류의 최소 ACK만 사진/시간을 보강하고 일반 MSG·이력의 명시적 교체는 유지합니다.
- 방 선택은 페이지 UUID별 증가 순번과 인증된 요청 헤더 도착 순서를 함께 검사합니다. reader 객체·연결 attempt가 바뀐 보류 요청은 거절합니다. 128페이지 순번 보관 상한은 오래된 순번을 버리지 않고 새 페이지를 거절하며 재연결 시 초기화합니다. 이는 공유 worker에 수락한 의도이며 카카오 ACK나 탭별 독립 활성 방 보장이 아닙니다. 일반 poll은 다른 탭의 선택을 반복 탈취하지 않습니다.
- D2 후속 보완은 방/계정 generation/연결 attempt/객체로 선택 의도를 추적합니다. selectRoom과 flushSelection은 자기 view 수락 뒤에만 자동 history를 제출하고, 거절된 의도는 poll·revision·focus·cache 무효화로 풀리지 않습니다. advanceRoom/직접 maybeSeen도 같은 gate를 씁니다. 진행 중 view는 intent가 소유하므로 대기 중 cache 무효화도 실제 거절을 버리지 않습니다. 재선택·수동 history는 새 의도, 재접속 restore는 userSelected=false를 유지하며 view 수락 후 이력만1회 복구합니다. freshness/포커스 부족은 보류, 실제 view 거절과 기존 history busy409는 구분합니다. 원래 후기 재검토의 “D2 부분 해결”은 이 후속 경로를 대상으로 했으며 최초 보고서를 덮어쓰지 않습니다.
- 수동 조회 P3 보완에서는 manual 의도를 pendingSelection에 보관해 checking 중 눌렀던 loaded 방 조회가 fresh/view 수락 후1회 실행되도록 했습니다. 같은 의도의 반복 클릭은 공유하고, 방/계정 generation/attempt가 바뀌면 폐기합니다. 실제 view 거절을 자동 재시도하지 않고 기존 history busy409/불명 결과 처리와 userSelected를 유지합니다.
- 메타데이터 대기 중 선택이 바뀐 history/context/read/photo는 활성화 전에 중단합니다. 명시적 텍스트 전송 의도는 기존 계약대로 유지합니다. 새 UI는 viewOrdering 광고가 없는 실행 중 구 서버에 기존 요청 형식을 쓰며, 구 서버 결함 해결에는 재시작이 필요합니다.
- 동적 OM/OD 보강은 확인된 기존 참여 방의 선택적 SYNCLINK/INFOLINK만 사용합니다. 합계6.5초·방당최대3회·3초 이후 새 push 조건을 적용하고 늦은 응답을 폐기합니다. 자동 입장·발송은 없으며 본인 참여 확인 전 전송은 계속 차단합니다. LOCO의 기존 timeout+10초는 SHIP/DNS부터 한 번만 계산하며 POST 전 실패/이후 불명을 구분합니다.
- 설정 잠금은 계정 epoch 소유자만 해제합니다. 같은 계정의 재연결은 자기 잠금을 해제하되 이전 generation의 결과를 화면에 적용하지 않습니다. LEFT 이벤트의 현재 본인 식별 형식은 별도 근거가 필요하며 해석을 변경하지 않았습니다.
- 독립 검토는 기존 빌트인 역할을 재사용한 읽기 전용 검토였습니다. 새 custom role 발견/실행이나 자식의 독립 런타임 검사를 주장하지 않습니다. 두 CLI/artifact 집계 지적은 수정했고 최종 실제 근거 범위도 재검토했습니다.
- 초기 실패·RED는 비공개 원본을 보존했습니다. fixture의 인증 대기/이력 준비/재생성 시점과 수집기 완료 플래그 교정은 제품 결함과 구분합니다. 과거 vendor 하네스는 manifest 검증 자료로 보존합니다.

## 문제 재현 시 조사 순서

현재 성공 사례를 전체 미해결로 되돌리지 않습니다. 남은 실패가 재현됐을 때 다음 순서로 목표·입력·소유 파일·의존성·통과 기준·자원 lease를 확정합니다.

1. **상대방 읽음1**: 권한 있는 APK 확보·버전/SHA256 → REA/JADX 정적 경로 → 별도 승인된 공식 앱 동작 비교 → 상태/프로토콜 계약 → 최소 수정 → 합성/로컬 통합 → 승인된 상대방 동일 메시지1 확인.
2. **사진 발송**: 원본 준비·업로드·메시지 등록·수신 단계를 분리해 현 소스/고정 공개 소스/APK 근거를 비교합니다. LOCO의 ECONNRESET 주체·원인은 HTTPS 성공만으로 확정하지 않습니다. 임의 WRITE·프로필 위장·자동 재시도는 도입하지 않습니다.
3. **대화방 이름**: CHATINFO·메타·참가자·오픈링크와 로컬 별칭 우선순위를 대조하고 정확한 방/종류 매핑을 검사합니다.
4. **오픈채팅**: 종류·링크·본인 역할/mute/권한을 보수적으로 확인한 뒤 텍스트·사진·답장·읽음을 각각 설계/검증합니다.

APK/Android·REA 도구와 권한은 해당 PC에서 확인합니다. REA CLI·별도 MCP subprocess·현재 세션 직접 MCP 연결을 구분하고, 샘플 APK 성공을 카카오톡 분석 성공으로 바꾸지 않습니다. APK·원본을 외부 서비스에 업로드하지 않습니다.

## 재개와 저장소 관리

새 clone은 README의 런타임/고정 소스/패키지를 준비하고 운영 문서대로 새 작업을 시작합니다. 과거 agent ID·계정 승인·다른 PC의 절대 경로/장부를 재사용하지 않습니다. 서버 코드 적용에는 사용자 초안 보관·세션 정리 후 전체 stop/start/open/새QR이 필요합니다.

공유 파일은 제품/테스트/준비 도구·잠금 파일·라이선스·UI 시안·하네스 정의입니다. 로컬 원본·샘플·실행 근거는 기존 Git 제외를 유지합니다. 사용 종료가 입증된 합성 브라우저 프로필은 검증된 압축 보관 후 원본 폴더를 정리하고, 프로세스 상태가 불명확한 프로필은 보존합니다. 실제 사용자 Chrome·LOCALAPPDATA 인증/설정·사용 중인 런타임/의존성은 정리 대상으로 삼지 않습니다.

커밋 전에는 Git 후보와 미추적 신규 모듈을 함께 확인하고 민감정보·raw 응답·원본 포함 여부를 검사합니다. 커밋/push는 별도 사용자 요청 범위에서 수행하며 force push하지 않습니다.
