# Web-Kakao 후속 작업 계획

2026-10-16 기준. 이 문서는 다른 PC의 clone에서도 읽을 수 있는 후속 계획이다. 현재 기능·제약과 검증 이력은 [README](../README.md), 역할과 배정 규칙은 [운영 문서](OPERATING.md)를 기준으로 한다. 비공개 진단 보고서·실행 장부가 없어도 이 두 문서로 새 계획을 만들 수 있어야 한다. 아래 실제 읽음·사진·이름·오픈채팅 단계는 실행 결과가 아니다. 모든 작업에 목표·입력·배타적 소유 파일·의존성·통과 기준·필요 자원 lease를 확정한 최신 패킷을 전달한다.

## 인수인계 상태

- 내부8종의 상태·화면 결함과 검수 중 찾은 WRITE 응답번호 충돌을 보완했다. Node168개(신규36개)가 통과했다. Chrome29분류와 Python23개는 수정 과정에서 실제 통과했고 최종 protocol 보완 차수에서는 의존·지문을 확인해 재사용했다.
- 이후 APK 없이 기존 이름 없는 방의 제한적 CHATINFO 보완, 인증 사용 시점 만료, 기한 있는 로컬 API 요청과 복귀 갱신을 구현했다. 추가 QA에서 찾은 최초 방 선택·폴링의 이력 누락 경합도 수정했다. 새23개를 포함한 Node191개·격리 Chrome37분류가 통과했다. 실제 방 이름·절전·장시간 관찰은 미실행이며 실서버를 재시작하지 않았다.
- 실제 상대방 읽음1, 사진 도착, 일부 방 이름, 오픈채팅 지원은 미해결이다. 합성 통과로 해결 판정을 바꾸지 않는다.
- 이전 분석 환경에는 카카오톡 APK가 없었고 Android 준비는 다른 PC에서 진행할 예정이었다. 새 PC에서는 도구·APK·사용권을 다시 확인하며 과거 환경 상태를 그대로 가정하지 않는다.
- Git으로 역할·스킬·계획 절차를 공유한다. 과거 대화·실행 중 세션·인증·분석 원본·발송 승인은 이전하지 않는다. 새 clone은 새 run을 만들고 필요한 실제 작업은 다시 대상을 확인받는다.

APK가 없으면 Android 분석은 미실행으로 유지한다. 다른 PC의 사용 권한 있는 Windows 설치본을 정적 분석하는 대안도 있다. 사용자는 다른 PC에 PC 카카오톡이 있다고 답했으며, 아직 파일·버전·해시는 받지 않았다. [PC 설치본 분석 준비](../tools/pc_analysis/README.ko.md)로 앱 실행·로그인 없이 버전·SHA-256부터 확인한다. 네이티브 엔진 준비와 PC/태블릿 프로필 차이를 검증하며, PC 경로에서 찾은 사실을 Android에도 적용된다고 가정하지 않는다. 공개 소스 대조·합성·복귀 처리 작업은 이 입력과 독립적으로 진행한다.

## 2. 사진 발송

analyst가 정확한 APK 또는 권한 있는 PC 설치본에서 업로드 연결·프레임·파일 바이트·COMPLETE·메시지 생성 경로를 추적한다. 분석 대상 버전·해시와 접속 프로필 차이를 남긴다. architect가 SHIP/POST 전후 실패와 결과 불명 경계, worker가 수정할 파일, QA의 정상/거부/소켓 종료/중복 기준을 제안한다. 기존 clientId+내용 해시, 무재전송 계약을 보존한다. 근거 없는 추가 WRITE를 하지 않는다.

합성 media-wire/reply-upload와 Chrome의 선택·붙여넣기·미리보기·취소를 먼저 확인한다. 과거 실제 발송 6회 승인은 모두 소진됐다. 추가 발송은 새 대상·사진·횟수·영향 승인 후에만 한다. POST 수락·바이트 쓰기·COMPLETE·수신 기기의 실제 도착을 각각 기록한다. 사진이 수신 기기에 실제 표시되어야 해결이다.

## 3. 대화방 이름

기존 이름 없는 방도 CHATINFO로 보완하도록 구현·합성 검증했다. 최초 목록 이후 연결당 최대8개·직렬·방당1회이며 ID 일치 응답의 제목만 갱신한다. 별칭·멤버십·읽음 위치·이력·방 종류·발송 지원은 보존한다. 실제 단절은 종료하고 선택적 메타 오류는 건너뛴다. 원래 문제 방의 실제 이름을 대조한 상태는 아니다.

다음은 별도 승인된 실제 목록 확인으로 제목과 같은 방인지 대조하고, 남은 오픈링크/부분 참가자 이름의 근거를 조사한다. 개인 모바일의 제목과 서버 제목·웹 별칭을 구분한다. 이름 복구로 발송 가능 여부를 바꾸지 않는다.

## 4. 오픈채팅 지원

현재 unknown/지원 분류 차단을 유지한 채 타입·링크·권한·메타데이터 경로를 조사한다. 텍스트/답장/사진/읽음을 각각 설계·검증하고 이름 수집과 전송 지원을 분리한다. 로컬 차단과 서버 거부를 구분한다. 합성 검사를 통과한 뒤 별도 승인된 대상에서 기능별 실제 송수신을 확인한다. 미확인 종류 일괄 허용과 자동 발송 시험은 금지한다.

## 새 세션에서 재개

현재 사용자는 카카오톡이 설치된 다른 Windows PC에서 이어가기로 했다. 저장소를 clone하거나 기존 clone에서 `git pull --ff-only origin main`한 뒤 아래 문서와 프롬프트로 시작한다. 이 PC의 실행 기록·인증·개인 설정·런타임·분석 원본은 Git에 포함하지 않으므로 새 PC에서 필요한 것만 준비한다.

우선순위는 **PC 설치본의 버전·SHA-256 → 네이티브 분석 도구/역할 확인 → 읽음1·사진 업로드·오픈채팅 경로 조사**다. 이번 수정본의 실계정 QA는 미실행이며, 세 기능은 QA만 남은 구현 완료 상태가 아니다. 기존 일반1:1 읽음 실패·사진 미도착·오픈채팅 로컬 차단을 기준으로 조사한다. APK 없이 가능한 모든 방법을 시험했다고 해석하지 않는다.

새 역할·스킬이 현재 세션의 목록에 없으면 먼저 대상 디렉터리에서 새 세션을 시작한다. 전역 설정이나 권한 모드를 바꾸지 않는다.

```powershell
# 먼저 clone한 저장소 루트로 이동한다.
codex -C (Get-Location).Path
```

새 세션에 전달할 요청:

```text
$harness README.md, AGENTS.md, .harness/OPERATING.md와 .harness/FOLLOWUP.md를 읽어줘.
tools/pc_analysis/README.ko.md도 읽고, 카카오톡이 설치된 이 Windows PC에서 조사를 이어가줘.
부모 cwd와 커스텀 역할 6개·프로젝트 스킬 발견을 확인하고,
작은 읽기 전용 커스텀 자식 하나로 실행 점검을 해줘.
먼저 앱 실행 없이 설치 EXE의 버전·SHA-256을 확인하고,
REA의 Windows 네이티브 분석 엔진과 실제 도구 접근·적합한 역할을 확인해줘.
이전 Android/JADX 시험을 PC EXE 분석 성공으로 취급하지 마.
PC 프로토콜과 웹의 Android 태블릿 접속 프로필 차이를 구분해서
상대방 읽음1·사진 업로드 완료·오픈채팅의 조사 계획과 새 run을 만들어줘.
로그인·기기 변경·실제 읽음·메시지·사진 발송·제품 수정은 시작하지 마.
REA는 명시적으로 배정된 lease 아래 doctor 범위만 확인하고,
APK가 없으면 Android APK 분석만 미실행으로 유지해줘.
PC 설치본의 정적 분석은 입력·도구·사용권과 별도 배정을 확인한 뒤 진행해줘.
```

새 세션도 실제 생성 응답을 확인해야 하며 이 명령 자체는 성공 보장이 아니다. 과거 run이 없는 clone에서 기존 실행 재개를 시도하지 않는다. 준비가 된 후 최신 입력에 맞춰 APK·PC 정적 분석·공개 소스/합성 작업 중 가능한 범위로 새 run을 만든다. 다른 OS의 실행은 별도 검증 대상이며 현재 준비 도구·Chrome fixture는 Windows 사용을 기준으로 한다.
