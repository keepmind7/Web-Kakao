# 초기화·방 이름 조회 수정 — 2026-11-02

로컬 `main`의 `15e405f`와 [앞선 진단](DIAGNOSIS_20261102.ko.md)을 기준으로 D1·D2를 수정했다. 지정한 합성·계정 없는 로컬 통합 범위는 **검증 성공**이다. 기존 진단 문서와 실패 기록은 보존했다. 실제 계정·기존 실행 서버·로그인에는 접근하지 않았으며 커밋·push도 하지 않았다.

## 수정한 동작

**D1: 개인 설정 초기화 뒤 이전 요청이 설정을 복원하는 경합.** `/api/preferences`의 본문 수신 전에 요청 세대를 포착하고, 유효한 초기화를 수락하면 이전 세대를 폐기한다. HTTP → reader manager → preference store → 파일 게시·메모리 반영까지 같은 유효성 검사를 전달한다. 초기화가 실패해도 이전 의도는 되살리지 않으며, 초기화 이후 새로 요청한 설정은 저장할 수 있다. 잘못된 본문·CSRF 요청은 정상 요청의 세대를 폐기하지 않는다. 재접속과 reader 교체도 이전 요청을 차단한다.

변경 파일은 `server.mjs`, `reader-manager.mjs`, `preferences.mjs`다. 기존 방 별칭 저장 순서 보호도 유지했다. 파일 저장 후 HTTP 응답만 거절하는 방식으로 처리하지 않았다.

**D2: 실제 요청 전에 취소된 방 이름 조회의 기회 소진.** `reader-session.mjs`에서 대기 예약과 실제 CHATINFO 시도를 구분했다. 선택이 바뀌어 발송 전에 폐기된 작업은 나중에 사용자가 그 방을 다시 선택하면 조회할 수 있다. 실제 요청을 보낸 뒤의 거절·기한 초과·늦은 응답은 기존대로 자동 재시도하지 않는다. 초기 8개 복구와 직렬 실행도 유지했다. 소비자가 없던 `titleInFlight` 상태를 제거했다.

## 사진 취소 관측

네 탭 사진 검사에 Chrome Network 종료 이벤트 종류·오류·HTTP 상태와 합성 요청별 서버 종료 연결을 추가했다. 기존 단언·시간 기준과 제품 사진 코드는 바꾸지 않았다.

관측 버전은 한 번 실행해 3조건을 통과했다. 이번에는 취소된 요청이 `loadingFailed / net::ERR_ABORTED / canceled:true`로 끝났고, 같은 합성 식별자를 재요청한 GET 3건은 HTTP 409로 정상 종료했다. 동시 요청 상한 2, 상류 작업 잔여 0과 전용 자원 정리를 확인했다. 앞선 진단의 `canceled:false` 2건은 재현되지 않았다. **당시 실패의 원인은 미확인이며, 이번 통과를 사진 결함 해결로 해석하지 않는다.** 과거 2/3 실패 기록도 유지한다.

## 남은 사항

- **D3의 완료 이력 응답 재수용:** 재전달을 주입한 합성 경계는 남아 있다. 실제 서버의 packetId 재사용·roomId 없는 정상 응답 계약과 SDK timeout 동작을 확인한 뒤 수정해야 한다. 이번에는 `reader-protocol.mjs`를 바꾸지 않았다.
- **방 전환 지연:** 이전 방의 이미 보낸 조회 결과는 보존하면서 후속 페이지 요청만 멈추는 개선은 별도 설계·검증이 필요하다. 이번 수정으로 메시지·사진 표시 속도가 개선됐다고 측정하지 않았다.
- **Windows 설정 저장 비용:** 권한 검사를 생략하거나 캐시하지 않았다. Python helper의 시작 비용과 실제 ACL 검사 비용은 아직 분리 측정하지 않았다.
- **실제 계정·다른 OS 회귀:** 미실행이다. 로컬 합성 결과를 상대방 화면의 읽음·실제 사진 도착 증거로 확대하지 않는다.

## Rust 검토와 적용

핵심 대화 서버와 웹 화면은 JavaScript/Node.js이고, Python은 실행·준비·OS 검사 도구에 쓰인다. 현재는 두 언어를 유지하는 편이 낫다. Rust는 Windows 권한 검사 helper를 동일 조건에서 비교할 후보이며, 전면 재작성이나 Rust 성능 비교는 실행하지 않았다. 근거와 실험 조건은 [언어 검토](RUST_ASSESSMENT_20261102.ko.md)에 남겼다.

서버 모듈 변경을 실제 실행에 적용하려면 작성 중인 글을 보관하고 로컬 세션을 정리한 뒤 서버를 재시작하고 새 입장·QR 승인을 진행해야 한다. 이번 작업에서는 기존 서버를 재시작하지 않았다. 실행 절차는 [README](../README.md)의 실행과 종료 안내를 따른다.
