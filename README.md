# Web-Kakao

기존 카카오톡 계정의 대화방을 노트북 브라우저에서 조회하고 메시지를 주고받는 **Windows용 로컬 웹 클라이언트**입니다. 이 PC에서 실행한 Node 서버가 카카오톡 서버와 통신하며, 브라우저는 로컬 서버의 화면을 사용합니다.

일반 대화·읽음·사진·답장은 사용자 확인 사례가 있습니다. 모든 방과 장시간 사용을 검증한 정식 카카오톡 대체 앱은 아니며, **사진 발송과 오픈채팅 발송은 현재 정상 동작을 보장하지 않습니다.** 기능별 제한과 확인할 항목은 문서 마지막의 **알려진 문제와 QA**를 확인하세요.

## 주요 기능

- 휴대폰 카카오톡의 QR 승인으로 로그인
- 기존 대화방 목록, 최근 이력, 실시간 메시지 조회
- 일반 방의 텍스트·인용 답장·사진 발송
- 받은 사진 표시·확대·명시적 다운로드
- 방별 별칭·고정·알림·필터, 불러온 메시지 검색
- 읽음 동기화 옵션, 새 메시지 배지
- 라이트·다크·시스템 테마, 좁은 화면의 목록/대화 전환
- 같은 서버 세션에서 결과 불명 전송을 확인하고 경고 정리

방당 표시 캐시는 최근 50개입니다. 추가 이력 조회가 가능하지만 계정의 전체 과거 이력 보관·복원을 보장하지 않습니다.

## 실행 환경과 의존성

| 구성 요소 | 필요 조건 |
| --- | --- |
| 운영체제 | Windows x64. 현재 실행·보안 도구는 macOS/Linux 및 Windows 32비트를 지원하지 않습니다. |
| Python | 3.11 이상. `py -3 --version`으로 사용할 실행기를 확인하세요. |
| Node.js | 프로젝트 도구로 준비하는 고정 버전 24.21.0. 전역 Node 설치는 필요 없습니다. |
| 브라우저 | Chrome 또는 Edge 권장. Windows 기본 브라우저로도 열 수 있습니다. |
| 휴대폰 | 최초 QR 로그인과 기기 승인을 진행할 카카오톡 |
| 네트워크 | 최초 런타임·소스·패키지 준비 및 실제 카카오톡 연결에 필요 |

Python 실행·준비 도구와 테스트는 **표준 라이브러리만 사용**합니다. [requirements.txt](requirements.txt)에 이 조건을 명시했으며, 현재 추가 pip 패키지는 없습니다. 다음 명령은 Python 의존성 목록을 적용하는 표준 진입점입니다.

```powershell
py -3 --version
py -3 -m pip install -r requirements.txt
```

`requirements.txt`가 Python 자체·Node·브라우저를 설치하지는 않습니다. Node의 `tsx`, `bson`, `qrcode-terminal` 등은 아래 준비 도구가 저장소의 잠금 파일을 사용해 `npm ci --ignore-scripts`로 설치합니다.

Android APK, BlueStacks, PC 카카오톡, REA·JDK·JADX·Ghidra·ADB는 **일반 웹 실행에 필요하지 않습니다.** 이들은 선택적인 프로토콜 분석용 도구입니다.

## 처음 설치하기

가능하면 `C:\src\web-kakao`처럼 짧은 경로를 사용하세요. 프로젝트와 ZIP 내부·임시 경로를 합친 길이에 따라 Windows 경로 제한이 생길 수 있습니다.

```powershell
git clone https://github.com/keepmind7/Web-Kakao.git web-kakao
cd web-kakao

py -3 -m pip install -r requirements.txt
py -3 tools/prepare_node_spike.py
py -3 tools/fetch_source_spike.py modern
py -3 tools/fetch_source_spike.py legacy
py -3 tools/prepare_spikes.py --install-dependencies

py -3 tools/local_web.py start --gap-probe --messaging
py -3 tools/local_web.py open --browser chrome
```

Python Launcher가 없다면 같은 3.11 이상 실행기로 모든 `py -3` 명령을 바꿉니다. 예를 들어 `python --version`이 조건을 충족하면 `python tools/local_web.py ...`를 사용합니다. 이 실행기가 Node 서버의 Windows 보안 helper에도 전달됩니다.

- 준비 단계는 검증된 고정 Node ZIP·공개 소스·npm 패키지를 `local-only/`에 보관합니다.
- 소스 커밋과 다운로드 해시·패키지 무결성을 확인합니다. 회사 프록시/TLS 검사 환경에서는 허용된 연결을 사용하며 인증서 검증을 끄지 않습니다.
- 준비 도구는 원래 소스와 제3자 라이선스를 보존합니다. Node 설치 스크립트는 실행하지 않습니다.
- `--help`는 준비·다운로드·계정 로그인을 시작하지 않습니다.
- 새 PC에는 인증·개인 설정·APK·과거 실행 기록이 Git으로 복원되지 않습니다.

## 평소 실행과 종료

준비를 마친 뒤에는 프로젝트 루트에서 같은 Python 실행기로 다음 명령을 사용합니다.

```powershell
py -3 tools/local_web.py start --gap-probe --messaging
py -3 tools/local_web.py open --browser chrome
```

Chrome 대신 Edge를 사용하려면 `open --browser edge`, Windows 기본 브라우저를 사용하려면 `open`만 실행합니다. 이미 같은 모드의 서버가 실행 중이면 `start`는 기존 서버를 유지하며, 화면만 다시 열 때는 `open`만 필요합니다.

1. 명령이 새로 연 브라우저 탭에서 **QR 로그인 시작**을 누릅니다.
2. 휴대폰 카카오톡으로 스캔하고 표시된 승인 절차를 진행합니다.
3. **대화방 불러오기**를 누르고 사용할 방을 선택합니다.
4. 일반 텍스트는 Enter로 전송하고 Shift+Enter로 줄바꿈합니다. 한글 조합 중 Enter는 전송하지 않습니다.
5. 메시지 메뉴로 답장·복사를 사용하고, ＋ 또는 이미지 붙여넣기로 사진을 준비합니다. **미리보기만으로는 발송하지 않으며 전송 버튼을 눌러야 합니다.**

사진 원본은 20MiB·4천만 픽셀 이하, 브라우저 변환 결과는 10MiB 이하여야 합니다. HTTPS 사진 모드에서는 JPEG·PNG·WebP를 **JPEG로 변환해 전송**하며 투명한 부분은 흰색으로 바뀝니다. 큰 사진은 화질을 조정해 10MiB 이내로 준비하고, 그래도 넘으면 전송 전에 안내합니다. 미리보기에는 실제 보낼 변환 결과가 표시됩니다. 준비 실패 문구 끝의 `[format]`·`[decode]`·`[encode]`·`[output-size]` 등으로 실패 단계를 구분할 수 있습니다. 준비 단계의 실패와 전송 후 실패는 별개입니다.

기본 주소는 `http://127.0.0.1:8787`입니다. **주소만 직접 열면 접근 권한이 부여되지 않습니다.** `open`은 검증한 로컬 서버에서 60초짜리 일회용 입장권을 받아 해당 탭에 접근 권한을 전달합니다. 카카오톡 QR 로그인과는 별도의 로컬 입장 절차입니다. 기존 미리보기나 다른 탭에는 권한이 자동 전달되지 않습니다.

`start`와 `open`은 같은 Windows 사용자·권한 수준으로 실행하세요. 불명확한 포트 소유자·실행 정보·권한을 만나면 덮어쓰기나 강제 종료 대신 중단합니다.

```powershell
py -3 tools/local_web.py status
py -3 tools/local_web.py stop
```

활성 로그인·대화 연결이 있으면 `stop`은 거부됩니다. 작성 중인 글을 보관하고 승인된 탭의 **로컬 세션 지우기**를 먼저 사용합니다. 로컬 세션 삭제와 서버 종료는 카카오톡 계정의 원격 로그아웃과 다릅니다.

## 연결·읽음·발송 동작

- 인증된 탭의 유지 연결이 하나라도 있으면 로컬 인증 보관의 1시간 강제 종료를 적용하지 않습니다.
- 마지막 유지 연결이 닫힌 뒤 2분이면 대화 연결·인증·사진 캐시를 정리합니다. 로컬 HTTP 서버는 계속 실행합니다.
- 절전·탭 중단·네트워크 단절로 유지 연결이 끊겨도 같은 유예를 적용합니다. 카카오 서버의 인증 만료 연장이나 토큰 갱신 기능은 아닙니다.
- **대화 조회 시 카카오톡에도 읽음 알리기**는 기본 OFF입니다. ON일 때 선택 방·전경·포커스·최신 메시지 표시·하단 위치 등의 조건을 확인해 읽음을 요청합니다.
- 직접 텍스트·답장·사진을 보내면 조회 읽음 옵션과 별개로, 허용된 해당 방의 읽음도 동기화합니다. 기존 상대 메시지가 읽음 처리될 수 있습니다.
- 연결 종료나 응답 누락으로 도착 여부를 모르면 **결과 불명**으로 남기며 자동 재전송하지 않습니다. 수신 기기를 확인한 뒤 경고를 닫습니다. 확인 버튼은 재발송 버튼이 아닙니다.
- 오픈채팅은 기존 참여 방의 종류·링크·본인 참여정보·권한을 확인한 기능만 허용합니다. 새 방 가입을 자동 수행하지 않습니다.

## 프로그램 구조

```text
브라우저 UI
    ↕ loopback HTTP / 로컬 탭 유지 연결
Node 로컬 서버 (127.0.0.1:8787)
    ├─ 브라우저 입장권·접근 세션·QR 인증
    ├─ 개인 설정·사진 프록시·전송 결과 관리
    └─ 대화 worker ↔ 카카오톡 서버
           └─ 고정 공개 소스 기반 프로토콜 클라이언트

Python 실행 도구
    └─ 런타임 준비·서버 시작/상태/종료·Windows 권한/프로세스 확인
```

| 경로 | 역할 |
| --- | --- |
| `experiments/local-web/index.html`, `app.js`, `style.css`, `theme.js` | 대화 화면·입력·테마·브라우저 상태 |
| `experiments/local-web/server.mjs`, `local-access.mjs`, `tab-presence.mjs` | 로컬 HTTP/API·입장권·탭 유지 정책 |
| `reader-manager.mjs`, `reader-worker.mjs`, `reader-session.mjs`, `reader-data.mjs` | worker 제어·프로토콜 요청·방/메시지 상태 |
| `media-upload.mjs`, `media-upload-https.mjs`, `photos.mjs`, `preferences.mjs` | 기본·실험 사진 전송·받은 사진 캐시·개인 설정 |
| `tools/`, `tools/locks/` | 실행·환경 준비·Windows 보안 helper·고정 npm 잠금 파일 |
| `tests/` | 계정 없는 단위·통합·격리 브라우저 검사 |
| `ui/` | 보존된 UI 비교 시안 |
| `AGENTS.md`, `.agents/`, `.codex/`, `.harness/` | 개발용 역할·스킬·운영 규칙. 앱 실행에 Codex는 필요하지 않음 |

`reader-*`, 사진·설정 모듈은 모두 `experiments/local-web/` 아래에 있습니다. 일반 사용 구조는 이 PC의 브라우저와 서버이며, 공식 앱을 상시 실행하는 브리지·원격 공개 서비스·터널을 사용하지 않습니다.

## 데이터와 개인 설정

- 인증·대화·사진은 메모리 중심으로 처리합니다. 서버 재시작 후에는 새 QR 인증이 필요합니다. 새로고침만으로 작성 중인 글이 복원된다고 보장하지 않습니다.
- 실행 정보·로그·정제된 진단은 `%LOCALAPPDATA%\WebKakao\<설치별 해시>\web-auth`, 개인 설정은 같은 설치의 `preferences`에 보관합니다.
- 설치별 해시는 프로젝트 절대 경로에서 계산하므로 폴더를 옮기면 다른 저장 위치를 사용합니다.
- **이 노트북에 개인 설정 저장**을 켜면 방 별칭·고정·알림·필터·읽음 옵션을 저장합니다. 저장을 끄면 저장 파일을 지우고 현재 실행의 설정은 유지합니다.
- Windows 사용자 접근 권한을 검사하며 설정 파일 자체를 암호화하지는 않습니다. `identity.key`는 계정 식별용 HMAC 키입니다.
- 받은 사진은 허용된 CDN에서 프록시로 읽으며 사진당 10MiB·동시 4개·캐시 합계 30MiB를 제한합니다. 사진 다운로드는 사용자가 명시적으로 선택합니다.
- 입장권 URL, QR·확인번호, 실행 정보, 인증 토큰, 실제 대화·사진, 개인 설정을 공유하거나 저장소에 추가하지 마세요.

`local-only/`, `docs/`, `evidence/`, 실행 장부·통신 기록·캡처·APK는 Git 제외 대상입니다. 공유되는 하네스 정의만 선택적으로 포함합니다. 기존 제외 규칙을 해제하거나 개인자료를 강제 추가하지 않습니다.

## 업데이트와 이전 버전에서 전환

로컬 변경을 확인한 뒤 소스를 갱신합니다.

```powershell
git status --short
git pull --ff-only
```

서버 모듈을 갱신했다면 작성 중인 글을 보관한 뒤 **로컬 세션 지우기 → stop → start → open → 새 QR 인증** 순서로 적용합니다. 파일 갱신만으로 이미 실행 중인 서버의 모듈이 교체되지는 않습니다.

build7에서 build8로 처음 전환할 때만 `stop --legacy`를 사용합니다. 이전 `local-only/preferences/`의 설정을 가져오려면 모든 서버를 종료하고 새 저장소가 아직 없을 때 다음을 실행합니다.

```powershell
py -3 tools/local_web.py stop --legacy
py -3 tools/local_web.py migrate-preferences --source ".\local-only\preferences"
py -3 tools/local_web.py start --gap-probe --messaging
py -3 tools/local_web.py open
```

이전할 설정이 없으면 `migrate-preferences`를 생략합니다. 이전은 원본을 보존하며 자동으로 실행되지 않습니다. build6 이하·손상된 실행 정보·점유된 포트는 강제 종료나 임의 삭제로 처리하지 말고 현재 프로세스와 상태를 먼저 확인해야 합니다.

## 사진 HTTPS 실험 모드

기본 사진 전송은 기존 LOCO 방식입니다. 구형 공개 소스를 바탕으로 **HTTPS 파일 업로드 → 별도 사진 메시지 등록**을 사용하는 선택 옵션을 제공합니다. 현재 노트북에서 작은 JPEG와 PNG 5종(작은 이미지·투명 이미지·약1/8/10.8MiB 원본)의 웹 전송과 모바일 카카오톡 도착을 사용자 확인했습니다. 다른 방 종류·WebP·재접속 후 전송은 추가 QA가 필요합니다. 로컬 웹사이트는 기존 HTTP 주소를 사용하며 nginx나 공개 HTTPS 서버는 필요하지 않습니다.

이 모드는 **JPEG·PNG·WebP 입력을 JPEG로 변환**해 업로드합니다. 투명 배경은 흰색으로 바뀌고, 최대 변4096픽셀·변환 결과10MiB 제한을 적용합니다. 큰 사진은 브라우저에서 JPEG 품질을 최대3단계로 조정하며, 이는 업로드 전 준비 과정입니다. 실제 업로드나 결과 불명 후 전송을 자동 반복하거나 기존 방식으로 전환하지 않습니다. 이전 웹 화면을 계속 열어 두었다면 작성 중인 내용을 보관한 뒤 Ctrl+F5로 변환 기능을 반영하세요. 이 화면 변경에는 서버 재시작·세션 삭제·QR 재로그인이 필요 없습니다. PNG 변환 후 모바일 도착은 위 5종에서 확인됐으며, WebP는 합성 검사만 통과했습니다. 원본20MiB 초과는 지원하지 않습니다. 업로드 경로의 보수적인 검증이 현재 서버의 정상 응답을 거부할 가능성도 남아 있습니다.

기존 서버가 실행 중이면 먼저 초안을 보관하고 웹의 **로컬 세션 지우기 → stop**을 직접 수행한 후 시작합니다. 이 과정은 현재 인증·연결을 정리하며 새 QR 인증이 필요합니다.

```powershell
py -3 tools/local_web.py start --gap-probe --messaging --photo-transport https-experimental
py -3 tools/local_web.py open --browser chrome
```

`status`의 `photoTransport`로 선택된 모드를 확인합니다. 다른 모드의 서버가 실행 중이면 `start`는 기존 서버를 유지하고 변경을 거절합니다. 기본 방식으로 돌아갈 때도 같은 세션 정리·종료 순서를 거친 뒤 `--photo-transport loco`로 시작합니다. 이 옵션을 생략해도 기본값은 `loco`입니다. 실제 발송 QA는 아래 원칙에 따라 대상·내용·횟수·영향을 정한 뒤 진행합니다.

## 개발·검증

실제 계정과 분리된 합성 검사입니다. 브라우저 검사는 Chrome·임시 프로필·임시 포트를 사용하며 개인 프로필과 사용 중인 서버를 대상으로 삼지 않습니다.

```powershell
py -3 -m unittest discover -s tests -v

$node = '.\local-only\runtime\node-v24.21.0-win-x64\node.exe'
$nodeTests = @(Get-ChildItem .\tests -Filter '*.test.mjs' | ForEach-Object { $_.FullName })
& $node --test @nodeTests
& $node tests/reader-browser-smoke.mjs
```

테스트 통과와 실제 카카오톡 도착은 별개의 증거입니다. 전체 테스트의 준비에도 위 Node·공개 소스·패키지가 필요합니다. `tools/verify_artifacts.py`는 비공개 `evidence/` manifest가 있는 해당 작업 복사본용이며, 새 clone의 일반 실행·테스트 필수 단계가 아닙니다.

사진 발송 방식의 계정 없는 비교 모델은 다음으로 실행합니다. 현재 LOCO, 구형 공개 소스 기반 HTTPS 업로드 후 메시지 등록, 공식 템플릿·수동 공유와 암호화 방식의 제약을 검사합니다. 전송 응답은 주입한 모의 값이며 실제 카카오 서버·TLS·수신 기기와의 호환성을 검증하지 않습니다. 앱의 기본 발송 경로를 변경하지 않습니다. 계약과 한계는 [비교 모델 안내](experiments/photo-method-simulation/README.md)를 참고하세요.

```powershell
& $node experiments/photo-method-simulation/run.mjs
& $node --test tests/photo-method-simulation.test.mjs
```

개발 하네스의 진입점은 [AGENTS.md](AGENTS.md), [운영 규칙](.harness/OPERATING.md), [후속 계획](.harness/FOLLOWUP.md)입니다. 새 환경에서는 과거 에이전트 ID·승인·실행 장부를 그대로 재사용하지 않고 새 작업과 필요한 도구를 확인합니다.

선택적 PC 정적 분석은 [PC 분석 안내](tools/pc_analysis/README.ko.md), APK 확보는 [Android 추출 안내](tools/apk_export/README.ko.md)를 참고하세요. 카카오톡 공개 API 범위는 [공식 메시지 API 문서](https://developers.kakao.com/docs/ko/kakaotalk-message/common)에 설명되어 있으며, 이 프로그램의 일반 대화 연결은 공식 공개 API를 사용한 정식 연동이 아닙니다.

## 알려진 문제와 QA

아래에서 **사용자 확인**은 실제 기기에서 확인한 사례이고, **합성 통과**는 모의 서버·격리 브라우저 검사입니다. 과거 한 번의 성공으로 모든 방·재접속·장시간 동작이 보장되지는 않습니다.

현재 노트북에서는 HTTPS 모드의 작은 JPEG와 PNG 5종의 웹 전송·모바일 카카오톡 도착을 사용자 확인했습니다. 기존 LOCO 방식의 과거 성공은 다른 PC에서 확인됐으며, 현재 노트북에서 발생한 이 방식의 실패 원인은 아직 미확정입니다. 보존된 작은 사진 실패는 업로드 완료 응답 전에 미디어 연결의 `ECONNRESET`이 먼저 기록됐습니다. HTTPS 대안의 성공만으로 기존 연결을 끊은 주체나 특정 코드 회귀를 확정하지 않습니다.

| 항목 | 현재 상태 / 다음 확인 |
| --- | --- |
| **단체 오픈채팅 텍스트 미도착** | 최신 사용자 QA에서 실패. 본인 참여정보 누락·충돌 처리와 전송 전 실패 분류는 보완했으나 수정 후 실제 도착 재확인이 필요합니다. 오픈채팅 사용을 보장하지 않습니다. |
| 오픈채팅 사진·답장·읽음 | 실제 확인 미완료. 방 종류·링크·본인 권한별로 개별 확인해야 합니다. 읽기 전용인 방을 강제로 허용하지 않습니다. |
| 초기 안 읽음 필터 | 초기 미읽음 수 집계는 합성 보완. 실제 로그인 직후 방 누락과 중복 가산 여부를 재확인해야 합니다. |
| 새로 활성화된 방 | 제한된 CHATINFO 재조회는 보완. 브라우저 새로고침 없이 목록에 나타나는지는 실제 재확인이 필요합니다. |
| 일부 방 제목·참여자 이름 | 메타·참가자·MEMBER 조회를 반영했으나 모든 실제 방의 올바른 이름을 확인하지 못했습니다. 로컬 별칭과 원격 제목을 구분합니다. |
| **기본 LOCO 사진 전송** | 일반 방과 나와의 채팅에서 실패가 남아 있습니다. 세션 정리·QR 재로그인과 64KiB 조각 전송 후에도 작은 사진의 완료 응답 전에 연결이 종료됐습니다. 이 경로의 원인은 미확정이며 HTTPS 대안의 성공과 구분합니다. |
| HTTPS 사진 실험 | 작은 JPEG와 PNG 5종(투명·약8/10.8MiB 원본 포함)의 웹 전송·모바일 도착을 사용자 확인했습니다. 이미지는 JPEG로 변환해 보냅니다. WebP 실제 도착, 일반 1:1·단체·오픈채팅의 종류별 결과·연속 전송·재접속은 추가 QA 대상입니다. |
| PNG 선택·준비 | 보완 후 이전에 실패한 PNG 5종의 전송과 모바일 도착을 사용자 확인했습니다. 이전 일반 준비 오류의 세부 원인은 미확정이지만 해당 사례는 통과했습니다. 격리 앱에서는 샘플1~10이 10MiB 이하 JPEG로 준비됐고, 11은 원본20MiB 제한 대상입니다. |
| 받은 사진 다운로드 | 합성 통과. 실제 기기의 파일 형식·저장 결과는 별도 QA가 필요합니다. |
| 읽음·직접 발송 후 모바일 배지 | 일반 읽음의 사용자 성공 사례가 있습니다. 새 발송 정책의 본인 모바일 배지와 다른 방에 미치는 영향은 자세한 재확인이 필요합니다. |
| 장시간·절전·네트워크 복구 | 탭 유지·유예·단절 처리는 합성 통과. 실제 1시간 초과·절전/탭 중단·재연결은 별도 QA가 필요합니다. 카카오 토큰 갱신을 보장하지 않습니다. |
| VS Code 내부 브라우저 | 현재 실행 도구는 외부 브라우저를 엽니다. 통합 브라우저용 입장권 전달은 미지원이며, Simple Browser는 iframe 차단에도 걸립니다. |
| 기존 설치·보안 경계 | 프로젝트 파일에 넓은 쓰기 권한이 있는 환경의 ACL 교정과 개인자료 이전은 자동 수행하지 않습니다. `tools/workspace_acl.ps1`은 기본 감사만 하며 실제 변경은 소유자 확인이 필요합니다. |
| 선택적 PC 정적 분석 | Ghidra 분석 helper는 점(`.`) 없는 프로젝트 임시 경로를 요구합니다. 사용자 이름 등에 점이 포함된 경로에서는 별도의 적합한 분석 작업 폴더를 준비해야 하며, 일반 웹 실행과는 무관합니다. |
| 다른 환경·배포 형태 | Windows x64 소스 실행 방식입니다. 설치형 EXE/MSI, macOS/Linux, 회사망·OneDrive 온디맨드·모든 브라우저 환경은 검증하지 않았습니다. |

실제 QA는 동의한 상대나 본인 시험방에서 진행합니다. 로그인·기기 변경·실제 읽음·문자/사진 발송은 대상·내용·횟수·영향을 확인한 뒤 수행하며, 이전 실험 승인을 재사용하지 않습니다. **상대방 화면의 같은 메시지 1 해제, 실제 수신 기기의 문자·사진 표시**로 판정하세요. HTTP202·서버 status0·업로드 완료 응답만으로 통과시키지 않습니다. 결과가 불명확하면 자동 반복하지 말고 수신 여부부터 확인합니다.
