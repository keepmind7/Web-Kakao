# Web-Kakao

기존 카카오톡 계정의 대화방과 메시지를 브라우저에서 조회하고 실시간으로 수신·답장하는 독립 웹 클라이언트를 연구한다. 공식 앱의 상시 실행이나 원격 데스크톱 대신 `브라우저 ↔ 자체 서버 ↔ 카카오톡 서버` 구조를 검토한다.

## Phase 2 진행 중

최소 읽기 전용 화면을 구현했다. QR 인증 뒤 대화방 불러오기 → 방 선택으로 메시지를 불러온다. 같은 연결의 MSG 수신을 표시하고 서버 메시지 ID로 중복·순서를 처리한다. 인증과 대화는 메모리에만 보관하며 실험용 인증 보관 한도는1시간이다. 서버 거부 응답에서는 인증·연결을 함께 정리하고 추가 시도를 막는다.

**현재 검증 범위:** 실제 계정의 목록63개와 참가자 이름 표시를 확인했다. 사용자 지정 방 이름은 미확인이다. 추가 읽기 경로 MCHATLOGS가 메시지24개·39개를 정상 반환했고 사용자가 중간 내역 표시를 확인했다. 이는 확인한 방의 결과이며 모든 방·전체 과거 이력의 완전성을 뜻하지 않는다. **사용자가 휴대폰 전원을 끈 뒤120초 동안 같은 연결·인증이 유지됐고 새 조회2회가 성공했다.** 장시간 유지·갱신·재접속 뒤 누락 복구·전송은 미검증 또는 미구현이다. 새 MSG 수신·변환은 관찰했지만 본문 대조·지속성 검증은 남아 있다. 아래 Phase 1 표는 종료 당시 결과다.

화면은 텔레그램 웹처럼 왼쪽 검색·대화 목록과 오른쪽 대화 영역으로 구성했다. 검색·방 선택·연결 설정·메시지 말풍선을 제공하며 발송은 아직 지원하지 않는다. 모의 화면 검사는 실제 계정 조회 성공을 뜻하지 않는다.

## Phase 1 종료

**2026-10-15 (Asia/Seoul), 최종 판단: 조건부 진행.** 가능성 조사와 최초 실연결 검증을 마감했다. 핵심 기능 전체 통과나 실사용 서비스 완료를 뜻하지 않는다.

본인 휴대폰 QR 스캔·확인번호 입력·승인 후 자체 서버에서 실제 인증 토큰을 받았다. 같은 노트북의 웹에서 읽기 전용 검사를 실행해 카카오톡 대화 서버 `LOGINLIST` 성공 응답(status0)과 **방 목록 배열62개**를 수신했다. 검사 후 연결을 종료했다. 공식 카카오톡 PC 앱과 원격 접속은 사용하지 않았다.

배열 개수는 전체 대화방의 완전성이나 과거 메시지 접근을 입증하지 않는다. 최초 휴대폰 승인은 운영 중 휴대폰 없이 계속 연결할 수 있다는 증거와 다르다. 현재 노트북이 임시 서버이므로 노트북을 끄면 로컬 서비스도 종료된다. 개인 노트북 종료 후 사용하려면 별도 상시 서버와 세션 유지 검증이 필요하다.

공식 공개 API는 일반 개인 대화방의 조회·수신·임의 방 답장을 제공하지 않는다. 카카오 로그인, 나에게 보내기, 조건부 친구 템플릿 발송과 일반 카카오톡 클라이언트 기능을 구분한다. [공식 메시지 기능](https://developers.kakao.com/docs/ko/kakaotalk-message/common), [2026년 공식 외부 연동 답변](https://devtalk.kakao.com/t/topic/148362/4).

## 로컬 실행

현재 실행 도구는 Windows x64와 Python 3.11 이상을 기준으로 한다. 준비 과정에서 Node24.21.0, 고정 공개 소스와 npm 의존성을 다운로드한다. 전역 설치 대신 프로젝트의 `local-only/`를 사용하며 외부 소스의 라이선스·고지를 보존한다.

```powershell
python tools/prepare_node_spike.py
python tools/fetch_source_spike.py modern
python tools/fetch_source_spike.py legacy
python tools/prepare_spikes.py --install-dependencies
python tools/local_web.py start --gap-probe
```

브라우저에서 `http://127.0.0.1:8787`을 열고 QR 로그인 → 휴대폰 스캔·승인 → **대화방 불러오기** → 방 선택 순서로 진행한다. 방을 누르면 메시지를 불러오고, 위의 **메시지 불러오기**로 이어 조회한다. 클릭당 최대8묶음만 요청하며 전체 과거 이력 완전성은 미검증이다. 서버가 제공한 제목·표시 이름이 없는 방은 이름 없음으로 표시한다. 최근 초기 표시는 LOGINLIST의 마지막 메시지를 사용하므로 현재 시각의 최신 메시지까지 도달했음을 보장하지 않는다.

실험 프로필은 Android 태블릿 SM-T733/Android14/앱26.1.2다. 비공식 연결 실험이며 서버가 등록·인증을 거부하면 중단한다. Phase 2의 인증·대화는 메모리에만 두고 인증 후1시간 뒤 정리한다. 이 한도는 카카오 서버의 토큰 만료 시간이 아니다. 로컬 세션 삭제·서버 종료는 원격 로그아웃을 뜻하지 않는다. 진행 중인 인증·대화 연결이 있으면 stop은 거부하므로 먼저 웹에서 로컬 세션을 지운다.

브라우저는 loopback HTTP를 사용하고, QR 인증의 카카오 서버 통신은 인증서 검증 HTTPS를 사용한다. 대화 서버 Booking은 TLS, 이후 Ticket/Carriage는 고정 소스의 V2SL 암호화 TCP를 사용한다. 외부 공개·터널·실제 메시지 발송 기능은 연결하지 않았다.

```powershell
python tools/local_web.py status
python tools/local_web.py stop
```

준비 도구는 제외된 `evidence/`에 다운로드 manifest를 새로 생성한다. 공개 저장소에는 당시 실행의 package-lock과 실측 보고서를 포함하지 않으므로, 새 설치는 당시의 전이 의존성을 완전히 고정한 재현과 다를 수 있다. `tools/verify_artifacts.py`는 비공개 로컬 보고서·manifest를 검증하는 도구이므로 해당 파일이 있는 작업 복사본에서 사용한다.

위 실행 명령은 실제로 중간 이력 보완을 확인한 `--gap-probe` 경로를 사용한다. SYNCMSG가 완료됐지만 알려진 최신 번호에 못 미치면 `MCHATLOGS`를 같은 방·같은 cursor 범위당 한 번만 요청한다. 응답의 명시적 방 ID가 일치해야 수용하며 거부 시 중단한다. 이 경로의 본인 계정 메시지 수신과 사용자 화면 대조를 확인했다. 플래그 없는 비교 모드에서는 보완 요청을 하지 않는다. 실행 중인 서버의 모드를 바꾸려면 로컬 세션 정리·서버 재시작·QR 인증이 필요하다.

## 검증

Phase 1 종료 시 Python16개와 Node30개 검사가 통과했다. 현재 Phase 2 코드는 Node67개·Python18개와 별도 모의 Chrome 검사가 통과했다. 모의 테스트 통과와 실제 계정 결과는 구분한다. Node 검사는 위 소스·의존성 준비가 필요하며 브라우저 검사는 로컬 Chrome을 별도 프로필로 실행한다.

```powershell
python -m unittest discover -s tests -v
& ./local-only/runtime/node-v24.21.0-win-x64/node.exe --test tests/local-web.test.mjs tests/room-probe.test.mjs tests/reader.test.mjs tests/reader-diagnostics.test.mjs tests/reader-performance.test.mjs
& ./local-only/runtime/node-v24.21.0-win-x64/node.exe tests/reader-browser-smoke.mjs
```

QR 인증·연결 검사의 기반 소스는 [tyeom/kakao-cli](https://github.com/tyeom/kakao-cli/tree/8dbbd4f7ed6b42542982252250622fa351af00e9)의 고정 commit이다. 원본의 일반 API 서버나 평문 계정 저장 기능을 실행하지 않고 제한한 실험 경로를 사용한다. `experiments/auth_preflight.py`는 초기 진단 기록용이며 현재 QR 실행기의 gate가 아니다.

이력 요청의 마지막 로그 번호 경계와 본문 상태 처리에는 [OpenKakao 고정 소스](https://github.com/JungHoonGhae/openkakao-cli/tree/6ca6ea2fd05a6660c4a80c0b61b43b416653d1d5)를 참고했다. 다른 클라이언트의 구현이 이 Android 프로필에서 동작함을 보장하지 않는다.

## 최적화

대화 내용과 QR이 달라질 때만 다시 그리고, 다른 방의 갱신으로 현재 읽던 위치가 이동하지 않게 했다. 이미 조회한 방은 재선택 시 캐시를 사용하며 추가 서버 조회는 위의 불러오기 버튼으로 요청한다. 상태 조회 주기는 화면을 볼 때1초, 숨겨진 탭은10초이며 다시 표시하면 즉시 확인한다.

메시지 정렬은 병합당2회에서1회로 줄이고, 참가자 별칭은 방별 맵으로 관리해 전체 별칭 반복 탐색을 없앴다. 기존 캐시·별칭 상한과 방 관계 검증은 유지한다. 합성 부하 검사는4,000개 별칭과4,000회 중복 push를 사용하며 실제 계정의 처리 속도를 보장하지 않는다. 현재 연결을 끊지 않고 검증했으므로 화면 변경은 새로고침 후, worker 최적화는 다음 연결 때 적용된다.

## 다음 단계

휴대폰 OFF 검증은2분 범위로 통과했다. 이후 장시간 유지·갱신·재연결·재인증, 실시간 본문 대조·재접속 뒤 누락 복구·중복·순서를 검증한다. 실제 전송은 대상과 정확한 내용을 승인받은 뒤 별도로 확인한다. 노트북은 현재 서버이므로 계속 켜져 있어야 한다. 화면의 추가 기능과 실사용 배포는 연결 검증 결과에 따라 판단한다.
