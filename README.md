# Web-Kakao

기존 카카오톡 계정의 대화방·메시지를 브라우저에서 조회하고 실시간으로 수신·대화하는 로컬 웹 클라이언트 연구 프로젝트다. 별도 채팅 서비스가 아니라 실제 카카오톡 계정과 기존 대화를 연결한다.

**2026-10-16 기준: Phase 3 진행 중, 로컬 사용 범위에서 조건부 진행.** 일반 텍스트 대화와 조회·수신은 확인했다. **상대방 화면의 읽음 `1` 해제, 사진 발송, 오픈채팅 발송은 미해결이다.** 완성된 카카오톡 대체 클라이언트로 판단하지 않는다.

## 사용 구조와 범위

```text
이 노트북의 브라우저 ↔ 이 노트북의 Node 서버 ↔ 카카오톡 서버
     127.0.0.1:8787
```

- Windows용 카카오톡 앱, 원격 데스크톱, 휴대폰 앱을 상시 실행하는 브리지를 사용하지 않는다.
- 최초 QR 로그인과 기기 승인에는 휴대폰 카카오톡이 필요하다. 현재 사용자의 승인 기기는 iPhone이다.
- 로그인 후 휴대폰 전원을 끈 상태에서 연결·조회를 120초 확인했다. 장시간 유지·세션 갱신까지 검증한 것은 아니다.
- 사용 중에는 이 노트북의 서버가 켜져 있어야 한다. 노트북을 끄면 웹도 종료된다. 외부 공개·터널·별도 상시 서버는 현재 범위에 포함하지 않는다.
- 공식 공개 API는 일반 개인 대화방의 조회·수신·임의 방 답장을 제공하지 않아 비공식 연결을 실험한다. 카카오 로그인·나에게 보내기·조건부 친구 메시지 기능과 구분한다. [공식 메시지 API 범위](https://developers.kakao.com/docs/ko/kakaotalk-message/common)

## 남은 주요 문제

### 상대방 화면의 읽음 `1`

웹에서 메시지를 읽었는데 상대방 카카오톡에는 `1`이 남는다. 앞서 사라졌다는 전달은 사용자가 정정했으며 **최근 상대방 메시지를 읽음 기준으로 선택한 수정본에서도 해제되지 않았다고 확인했다.**

NOTIREAD의 헤더·본문 `status0`은 요청에 대한 응답이며 상대방 화면 반영 성공을 입증하지 않는다. 실제 조회에서 요청 전후 `CHATINFO.lastSeenLogId`가 대상 위치 미만인 사례도 관측했다. 이 seen 필드와 상대방 읽음 워터마크의 의미가 같은지, 실패 원인이 무엇인지는 미확정이다.

전경·포커스·최신 메시지 표시·하단 위치·읽음 옵션을 확인한 뒤 요청한다. 과거 이력 누락이 읽음까지 막던 조건과 로컬 HTTP202를 완료로 기억하던 처리는 보완했다. 진단은 세션당 최대8개 방의 최초 읽음에서만 전후 조회하며 식별자 없이 비교 결과만 남긴다. 이 보완으로 실제 문제가 해결됐다고 보고하지 않는다.

### 사진 발송

SHIP·POST 성공 응답을 받아도 COMPLETE와 휴대폰 도착을 확인하지 못했다. 승인된 합성 PNG6회 모두 해결을 입증하지 못했으며 마지막 시험은 소켓 쓰기262,080바이트 뒤 약19.7초에 ECONNRESET이었다. 자동 재전송하지 않는다. 기존 발송 승인은 모두 소진됐으며 추가 실발송에는 별도 대상·내용 확인이 필요하다.

### 방 이름과 오픈채팅

빈 이름 필드·제목 메타·참가자 이름 파싱을 보완했지만 조사 시점의 일반 단체방5개는 이름 미확인으로 남았다. 알려진 방의 CHATINFO와 오픈링크 이름 보완이 후속 과제다. 오픈채팅은 종류·링크 관계를 보존하고 텍스트·답장·사진·읽음의 지원 여부를 분리해 각각 검증한다. 미확인 종류를 일괄 전송 가능으로 바꾸지 않는다.

## 로컬 실행

Windows x64, Python3.11 이상과 초기 다운로드를 위한 네트워크가 필요하다. Node24.21.0과 공개 후보 소스를 프로젝트의 `local-only/`에 준비한다. 전역 설치는 필요하지 않다.

```powershell
python tools/prepare_node_spike.py
python tools/fetch_source_spike.py modern
python tools/fetch_source_spike.py legacy
python tools/prepare_spikes.py --install-dependencies
python tools/local_web.py start --gap-probe --messaging
```

1. `http://127.0.0.1:8787`을 연다.
2. **QR 로그인 시작** → 휴대폰 카카오톡 스캔·승인 → **대화방 불러오기**를 진행한다. QR·확인번호·토큰을 저장소나 채팅에 공유하지 않는다.
3. 방을 선택하면 이력을 불러온다. 추가 조회는 상단 **메시지 불러오기**를 사용한다.
4. 지원되는 일반 방에서 텍스트를 입력한다. Enter는 전송, Shift+Enter는 줄바꿈이며 한글 조합 중 Enter는 전송하지 않는다.
5. 메시지의 마우스·우클릭 메뉴에서 **답장하기·복사**를 선택한다. 키보드는 메시지 포커스 후 Shift+F10 또는 메뉴 키, 화살표 이동, Escape 닫기를 지원한다.

`--gap-probe`는 SYNCMSG가 알려진 최신 범위에 못 미치면 같은 방·같은 범위의 MCHATLOGS를 한 번 확인한다. 명시적 방 ID가 일치하는 응답만 수용한다. 클릭당 최대8묶음·표시50개 제한이 있으며 전체 이력을 보장하지 않는다. `--messaging`이 있어야 전송·읽음 요청을 제공한다.

```powershell
python tools/local_web.py status
python tools/local_web.py stop
```

진행 중인 인증·연결이 있으면 stop은 거부된다. 먼저 웹의 **로컬 세션 지우기**를 사용한다. 로컬 세션 삭제·서버 종료는 원격 로그아웃과 다르다. 이전 실험 기기 SM-T733이 남아 재등록을 막는 경우, 해당 실험 기기임을 확인한 뒤 그 기기만 직접 로그아웃한다.

현재 실행 버전은 build6이고 실험 접속 프로필은 Android 태블릿 SM-T733/Android14/앱26.1.2다. 승인 휴대폰의 OS와는 별개다. 서버가 등록·인증을 거부하면 중단한다. 카카오 서버의 HTTPS·LOCO 통신과 브라우저의 loopback HTTP를 구분하며 외부 공개용 HTTPS 서비스는 구성하지 않았다.

## 데이터와 설정

- 인증·메시지·사진은 메모리에서 처리한다. 실험 인증 보관 한도는1시간이며 서버 재시작 시 재인증이 필요하다. 이는 카카오 서버의 토큰 만료 시간을 뜻하지 않는다.
- **이 노트북에 개인 설정 저장**을 켜면 이름·고정·방별 알림·필터·읽음 옵션을 계정별로 `local-only/preferences/`에 저장한다. Windows 사용자 접근 권한을 적용하지만 설정 파일 자체 암호화는 제공하지 않는다.
- 저장을 끄면 해당 계정의 설정 파일을 지우고 현재 실행의 설정은 유지한다. 작성 중인 글은 브라우저 메모리에만 있어 새로고침하면 사라진다. 방 이름 변경은 웹에만 적용된다.
- **웹에서 확인하면 카카오톡에도 읽음 알리기**는 기본 꺼짐이다. 켜도 현재 상대방의 `1` 해제 문제는 미해결이다.
- 받은 사진은 허용한 카카오 CDN에서 메모리 프록시로 표시한다. 사진당10MiB·동시4개·캐시30MiB로 제한하며 원본 주소를 브라우저 메시지 응답에 넣지 않는다.
- 알림은 본문 없이 무음으로 표시한다. 차단됐다면 Chrome 사이트 설정 → 알림 → 허용 후 새로고침한다. [Chrome 공식 안내](https://support.google.com/chrome/answer/3220216?hl=ko)
- 결과 불명인 전송은 자동 재시도하지 않는다. 재발송 전에 실제 도착 여부를 확인한다.

## 다음 조사: 다른 PC의 Android 에뮬레이터

이 노트북에는 에뮬레이터가 없다. **다른 PC의 사용 권한 있는 Android 환경에서 실제 카카오톡 동작과 APK를 확보해 읽음·업로드 경로를 분석**하는 것이 다음 단계다. 에뮬레이터는 분석 대상이며 상시 실행 브리지로 제품 구조를 바꾸지 않는다.

1. **정적 분석 준비:** 에뮬레이터에 Google Play로 카카오톡을 설치한다. APK 추출·코드 분석에는 로그인이 필요하지 않다. Windows용 PC 카카오톡 EXE는 Android APK와 별개다.
2. **APK 확보:** 아래 도구를 다른 Windows PC에서 실행해 base·split APK 전체와 버전·SHA-256 목록을 가져온다. 실제 기기 추출은 아직 미실행이고 서명·배포 진위는 별도 확인 대상이다.
3. **REA 분석:** 실제 버전·해시·클래스·메서드·호출 경로를 기록한다. 읽음의 방 진입·본인 읽음 위치·상대방 통보 순서와 사진의 업로드 연결·프레임·완료 처리를 웹 코드와 대조한다.
4. **실행 동작 비교:** 정적 분석과 구분해 공식 앱의 읽음 반영을 확인한다. 에뮬레이터 로그인은 별도 단계이며 기존 iPhone·연결 기기에 미칠 영향을 확인하고 사용자 승인을 받은 뒤 진행한다. 타인 데이터 접근이나 보호 기능 우회를 전제로 하지 않는다.
5. **회귀 확인:** 근거 확보 → 웹 수정 → 합성 검사 → 실계정·상대방 화면 대조로 판정한다. 실제 메시지·사진 발송은 대상과 내용을 확인받는다. 서버 성공 응답만으로 해결을 선언하지 않는다.

```powershell
python tools/prepare_android_adb.py
python tools/build_apk_export_kit.py
```

`local-only/apk-export-kit.zip`을 다른 PC에서 전부 풀고 `run.cmd`를 실행한다. ADB 설정·대상 선택·결과 ZIP 전달은 [APK 추출 안내](tools/apk_export/README.ko.md)를 따른다. 합성 검사5개와 공식 ADB 준비 검사는 통과했으며 실제 추출 성공을 뜻하지 않는다.

REA6.5.0·JDK·JADX를 로컬에 준비해 CLI·별도 MCP·공개 시험 APK의 패키지/메서드/참조 분석을 검증했다. **카카오톡 APK 분석은 미실행**이다. 부모 세션의 REA 전용 MCP 직접 연결이나 REA·codex-harness의 전용 연동을 가정하지 않는다. 하네스 helper는 역할·파일 소유권·인수인계 정리에 참고하며 Claude에서 그대로 실행된다고 보고하지 않는다.

웹 실행과 별도로 분석 환경을 준비하려면 다음을 사용한다. JDK·JADX 다운로드도 `local-only/`에 보관하며 APK는 외부 분석 서비스로 올리지 않는다.

```powershell
$nodeRoot = (Resolve-Path .\local-only\runtime\node-v24.21.0-win-x64).Path
& "$nodeRoot\node.exe" "$nodeRoot\node_modules\npm\bin\npm-cli.js" install --prefix ./local-only/rea --cache ./local-only/npm-cache --ignore-scripts --no-audit --no-fund --save-exact rea-agents@6.5.0
python tools/prepare_rea_android.py
python tools/rea_local.py doctor --label android-doctor
```

## 검증

최근 코드의 전체 Node132개·Python23개가 통과했다. Chrome 합성 검사도 통과했으며 이번 README 정리에서는 화면 코드를 바꾸지 않아 재실행하지 않았다. Chrome은 개인 프로필과 분리한 임시 프로필·합성 메시지로 실행해 마우스/우클릭 메뉴, 화면 경계, 580픽셀 폭의 시간 비중첩, 기존 답장·복사를 검사했다. 자동 검사 통과는 실제 읽음·사진 전송 성공을 의미하지 않는다.

```powershell
python -m unittest discover -s tests -v
$node = '.\local-only\runtime\node-v24.21.0-win-x64\node.exe'
$nodeTests = @(Get-ChildItem .\tests -Filter '*.test.mjs' | ForEach-Object { $_.FullName })
& $node --test @nodeTests
& $node tests/reader-browser-smoke.mjs
```

Windows의 테스트 자식 프로세스·임시 폴더 ACL·Chrome 실행 권한이 필요하다. 계정 인증·실제 발송은 자동 테스트에 포함하지 않는다.

## 파일 구성과 공개 제외 범위

| 경로 | 내용 |
| --- | --- |
| `experiments/local-web/` | 브라우저 화면·QR 인증·조회/수신·전송·설정·사진 처리 |
| `experiments/`의 다른 파일 | 모의 실험·초기 진단·명시적 승인 후에만 쓰는 발송 실험 도구 |
| `tests/` | 인증·권한 경계·대화·메뉴·업로드 프레임·APK 추출의 합성 검사 |
| `tools/` | 환경·런타임 준비, 서버 관리, REA 실행, APK 추출 키트 생성 |
| `tools/vendor/codex_harness/` | 참고용 하네스 helper와 원본 라이선스 |
| `docs/`, `evidence/` | 비공개 로컬 상세 보고서·실행 근거·manifest. Git에는 포함하지 않음 |
| `local-only/` | 런타임·소스 복사본·개인 설정·분석 대상·진단·추출 ZIP. Git에는 포함하지 않음 |

기존 `.gitignore`에 따라 `.env`, 자격증명·키·세션·원본 캡처·APK 및 `docs/`, `evidence/`, `.codex/`, `.harness/`, `_workspace/`, `local-only/`를 제외한다. GitHub의 README는 제외된 로컬 문서에 의존하지 않고 현재 상태와 실행 방법을 설명한다.

준비 도구는 새 환경에서도 필요한 `evidence/` manifest를 생성한다. 당시 package-lock은 공개하지 않으므로 전이 의존성까지 완전히 고정한 재현을 보장하지 않는다. `tools/verify_artifacts.py`는 비공개 문서·근거가 있는 작업 복사본에서 사용하는 로컬 검증 도구다.

## 단계별 이력과 참고 소스

- **Phase 1:** 공식 API 조사와 QR 인증·대화 서버 로그인·방 목록62개 수신 확인. 핵심 전체 기능 검증으로 종료한 것은 아니다.
- **Phase 2:** 기존 방·중간 이력·실시간 본문 대조, 휴대폰 OFF120초, QR 재인증 없는 수동 재접속 확인. 전체 이력·장시간 운영은 남았다.
- **Phase 3:** 로컬 텍스트·인용 답장·새 메시지 배지·방 이름·목록 정리·무음 알림·설정 저장·받은 사진 보기를 확장했다. 읽음 반영·사진 발송·오픈채팅은 위 미해결 범위를 유지한다.

QR·LOCO 기반은 [tyeom/kakao-cli 고정 커밋](https://github.com/tyeom/kakao-cli/tree/8dbbd4f7ed6b42542982252250622fa351af00e9), 채널·읽음 구조는 [node-kakao 고정 커밋](https://github.com/storycraft/node-kakao/tree/8512e4699e2cd4c26516b80d38b57b2f85a6cc8a), 이력 경계는 [OpenKakao 고정 커밋](https://github.com/JungHoonGhae/openkakao-cli/tree/6ca6ea2fd05a6660c4a80c0b61b43b416653d1d5)를 참고했다. 읽음 비교에는 [agent-messenger 고정 커밋](https://github.com/agent-messenger/agent-messenger/tree/53da74427357d8dda6caf0b21d35b700948681a1)을 추가 대조했다. 다른 구현의 존재는 이 접속 프로필에서의 성공 증거가 아니다.

분석·작업 관리 참고 프로젝트는 [REA](https://github.com/morluto/rea)와 [codex-harness](https://github.com/revfactory/codex-harness)다. 외부 소스의 라이선스·고지는 로컬 준비 과정에서 보존한다.
